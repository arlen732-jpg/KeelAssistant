# KeelAssistant 通用規範

## 技術棧

- .NET 8 (`net8.0-windows`)，`Nullable` 全開、`ImplicitUsings` 全開、`LangVersion=latest`
- WinForms（`UseWindowsForms=true`）作為常駐宿主
- 內嵌 ASP.NET Core（`WebApplication.CreateSlimBuilder` + `FrameworkReference Microsoft.AspNetCore.App`）僅用於跑 MCP Server
- `ModelContextProtocol.AspNetCore` 套件實作 MCP Streamable HTTP
- `Microsoft.Web.WebView2` 用於內嵌瀏覽器播放音樂
- 無單元測試專案、無 linter/formatter 設定檔（無 `.editorconfig`）

## 目錄結構

按「功能模組」分資料夾，每個資料夾內含該模組的服務類別＋（如有）UI Form：

```
Api/        MCP Server 宿主與工具方法（McpHost.cs, KeelTools.cs）
Alarm/      鬧鐘/計時引擎 + 響鈴視窗（AlarmEngine.cs, AlarmForm.cs）
Music/      WebView2 播放控制 + 播放視窗（MusicController.cs, MusicForm.cs）
Calendar/   Outlook COM 存取（CalendarService.cs）
Memory/     生活習慣記憶儲存（MemoryStore.cs）
Usage/      Claude 用量監控（ConfigLoader/CredentialStore/OAuthUsageClient/PricingTable/TranscriptScanner）
Time/       時間/星期/時段服務（TimeService.cs）
Models/     全專案共用資料模型，集中放在單一 Models.cs
```

`TrayApplicationContext.cs`（根目錄）是組裝根：建立所有模組單例、建置托盤選單、啟動 `McpHost`。新模組要接上系統，一律在此類別的建構子中 `new` 出實例並注入 `McpHost`。

## 命名規範

- 類別、方法、public 屬性：PascalCase
- 私有欄位：`_camelCase`（例：`_tasksPath`, `_gate`）
- 區域變數、參數：camelCase
- 常數：PascalCase（例：`OlFolderCalendar`），非全大寫 SNAKE_CASE
- 布林旗標：直述語意即可，不強制 `is/has` 前綴（例：`IsPlaying`、`_ready`、`_busy`）
- 執行緒安全鎖物件固定命名 `_gate`（見 `AlarmEngine`、`MemoryStore`）

## Import / Using 順序

```csharp
using System.Xxx;              // BCL
using KeelAssistant.Alarm;     // 專案內模組（依字母排序，KeelAssistant.* 分組）
using Microsoft.AspNetCore...; // 第三方套件
```

`namespace KeelAssistant.Xxx;` 一律用檔案範圍宣告（無大括號區塊）。

## 錯誤處理

- 參數缺漏/格式錯誤 → `throw new ArgumentException("缺少 xxx")`，訊息簡短中文，不含堆疊細節
- 狀態衝突（找不到資料、操作不允許）→ `throw new InvalidOperationException(...)`
- 外部依賴失敗（Outlook COM、HTTP）→ 包一層 `InvalidOperationException`/自訂例外並帶上原始 `ex.Message` 與 `ex` 作為 `innerException`：
  ```csharp
  catch (Exception ex)
  {
      throw new InvalidOperationException($"讀取 Outlook 行事曆失敗：{ex.Message}", ex);
  }
  ```
- 背景資源釋放（Dispose、停止音效/視窗）一律用空 `catch { }` 靜默吞掉，並加註解說明為何可以吞：
  ```csharp
  try { _player.Stop(); } catch { }
  ```
- 需要區分錯誤類型給呼叫端判斷時，定義專屬例外類別（見 `Usage/OAuthUsageClient.cs`）：
  ```csharp
  public sealed class RateLimitedException(string message) : Exception(message);
  public sealed class TokenRefreshException(string message) : Exception(message);
  ```

## 序列化/反序列化

- 一律用 `System.Text.Json`，不用 Newtonsoft
- 對外部 API 回應（如 OAuth usage）用 `[JsonPropertyName("snake_case")]` 對應官方 snake_case 欄位，C# 屬性維持 PascalCase
- 本機持久化檔案（`tasks.json`、`memory.json`）固定選項：
  ```csharp
  private static readonly JsonSerializerOptions JsonOpts = new()
  {
      WriteIndented = true,
      Encoder = System.Text.Encodings.Web.JavaScriptEncoder.UnsafeRelaxedJsonEscaping,
      Converters = { new JsonStringEnumConverter() }   // 有 enum 欄位才加
  };
  ```
  `UnsafeRelaxedJsonEscaping` 是刻意選擇，讓中文 label 直出成可讀字元，不要移除。
- 讀取容許註解/尾逗號的設定檔（`appsettings.json`）用：
  ```csharp
  new JsonSerializerOptions { ReadCommentHandling = JsonCommentHandling.Skip, AllowTrailingCommas = true }
  ```

## 日期/時間處理

- 一律用 `DateTime`/`DateTimeOffset`，本機時間用 `DateTime.Now`（不用 `UtcNow`，因為所有使用情境都是台灣本機助理）
- 對外顯示格式固定 `yyyy\\/MM\\/dd HH:mm[:ss]`（轉義斜線避免受地區設定影響）：
  ```csharp
  now.ToString("yyyy\\/MM\\/dd HH:mm:ss")
  ```
- 需要「HH:mm 當天，已過則明天」語意的輸入解析，用 `TimeOnly.TryParse` 搭配日期補算（見 `KeelTools.TryParseFireAt`）
- 與外部系統（Outlook Restrict 篩選字串）互動時固定用 `CultureInfo.InvariantCulture`，避免地區設定造成篩選失效

## ID 生成規則

- 短碼 ID：`Guid.NewGuid().ToString("N")[..8]`（見 `AlarmEngine.NewId`），用於 `tasks.json` 的任務 id
- 不用自增數字或組合式 ID

## 執行緒模型（本專案核心慣例）

- WinForms `System.Windows.Forms.Timer` 的 `Tick` 事件已在 UI 執行緒，可直接操作 UI/COM，不需再切換
- MCP 工具方法（`KeelTools`）執行在 ASP.NET Core 的執行緒池，凡是要碰 WinForms 控件或 Outlook COM（STA），一律經建構子注入的 `UiDispatcher`：
  ```csharp
  public static object StopAlarm(AlarmEngine alarm, UiDispatcher ui)
  {
      ui.Send(() => alarm.StopRinging());
      return new { stopped = true };
  }
  ```
- 有回傳值用 `ui.Send<T>(Func<T>)`，無回傳值用 `ui.Send(Action)`；內部例外會在 `UiDispatcher` 內被捕捉並於呼叫端執行緒重新拋出，維持呼叫端可 try/catch

## 註釋風格

- Public 類別/方法一律 `/// <summary>`，說明設計意圖或約束，不是重述型別
- 修改既有邏輯（非新增檔案）必須加變更標記，格式：
  ```csharp
  // 2026/06/25 - Arlen - 修「結束無法關閉、背景殘留」：說明原因與作法 - Start
  ...變更的程式碼...
  // 2026/06/25 - Arlen - 修「結束無法關閉、背景殘留」- end
  ```
  ⚠️ 新增 `.md` 或範例文件時，作者用 `[作者]` 佔位符；只有專案內**實際的歷史註解**才保留真實人名。
- 區塊分隔用 `// ── 標題 ─────`（全形破折號置中對齊）分隔一個類別內的不同職責區塊（見 `TrayApplicationContext.cs`、`KeelTools.cs`）

## COM Interop（Outlook，`Calendar/CalendarService.cs`）

- 用 late-binding（`Type.GetTypeFromProgID` + `dynamic`），不引用 Office PIA，避免綁定特定 Outlook 版本
- 所有 COM 物件（`app`/`ns`/`calendar`/`items`/`restricted`/`appt`）在 `finally` 區塊用 `Marshal.FinalReleaseComObject` 釋放，避免殘留 `OUTLOOK.EXE`；釋放邏輯集中在共用 `Release(object?)` 方法
- COM 的集合物件只能用 `foreach` 迭代（走 `IEnumVARIANT`），不可呼叫 `GetEnumerator()`
- 篩選字串（`Restrict`）固定用 `CultureInfo.InvariantCulture` 格式化日期，避免地區設定造成篩選失效
- 呼叫端一律經 `UiDispatcher.Send`（STA 執行緒要求）

## 設定檔管理

- `appsettings.json` 用 `ConfigLoader.LoadSettings` 讀，找不到檔案回傳 `new AppSettings()` 預設值，不拋例外
- 設定值有下限保護時在使用端 clamp（不在 model 層擋），例：
  ```csharp
  int interval = Math.Max(180, _settings.PollIntervalSeconds);
  ```
- 機敏資訊（OAuth token）不放 `appsettings.json`，讀寫 `~/.claude/.credentials.json`（見 `Usage/CredentialStore.cs`）
